# Fix plan — 2026-06-10 inspection

Companion to [`2026-06-10-inspection.md`](2026-06-10-inspection.md). Sequences the
findings into landable phases, each with the **fix shape** (signature/approach level, not
full impl). Pre-1.0: no back-compat constraint, interface/architecture free to change.

**Per-phase process (standing requirement):** start each fix by adding a failing test that
reproduces the finding (TDD doubles as verification), then fix, then the full gate —
`cargo fmt --check`; `cargo clippy --all-features --all-targets -D warnings` (+ no-default
and default configs where gated code is touched); `cargo doc --all-features --no-deps`;
`cargo test --all-features` (+ `-- --ignored` for real-subprocess tests on unix, Windows
for the degrade/job tests); `cargo check --target aarch64-apple-darwin` for any `sys/`
touch — then **≥2 independent review passes, fix until a clean pass**. `public-api.txt`
re-baselined on any surface change.

**Order rationale:** kill-safety first (it kills *innocent* processes — highest blast
radius), then the result-shape reshape while that code is fresh, then capture integrity,
then the independent subsystem clusters (resolution / pipeline / sys / security / stdin)
which can be reordered or parallelized freely, design block last (or gated — see Decisions).

---

## Decisions to confirm before execution

These four forks change the plan's size or shape. Recommendation given for each.

1. **Design block (Phase I, D1–D10) — do now or defer?** Pre-1.0 is the only cheap moment
   for the breaking reshapes (return `Outcome`, `Signalled` with signal number, etc.).
   **Recommend: do it now**, immediately after Phase A/B land the behavior (D1/D2 edit the
   same consuming-path functions — editing them once is the win). If deferred, file as a
   new ROADMAP item, not dropped.

2. **Stdin failure (B3): fail the run, or surface only when otherwise-OK?** **Recommend:**
   child's non-zero exit / signal wins (the "realer" failure); a stdin-writer error
   surfaces (new `Error::Stdin`) only when the run otherwise succeeded. Broken-pipe stays
   routine (never surfaced).

3. **Debug redaction (B4): how aggressive?** **Recommend:** `Command`/`CliClient` Debug →
   env *names* only + arg *count* (mirrors the existing handler/token presence-only
   redaction); `command_line()` stays the explicit, documented-as-secret-bearing escape
   hatch. `Invocation` → manual Debug (names/count), public fields kept for explicit
   assertions. Tradeoff: failed `assert_eq!(invocation, …)` diffs become less readable —
   acceptable for secret-safety-by-default.

4. **Pipeline per-stage `ok_codes` (B11): honor on inner stages, or document the strip?**
   The last-stage reset is defensible (a pipeline's success *is* pipefail). The inner-stage
   strip is not clearly right — `producer | grep.ok_codes([0,1]) | wc` arguably wants
   grep's 1 treated clean. **Recommend:** honor `ok_codes` for inner-stage cleanliness
   (`stage.code` clean iff in its `ok_codes`), keep the last-stage policy, and document
   both publicly. (Alternative: keep current behavior, document only.)

## Phase A — Kill-safety & run lifecycle (highest blast radius)

The recycled-pid + cancel cluster. **Core change:** consolidate the scattered watchdog
arming (currently split across `drive_to_exit_inner` and `stdout_lines`/`output_events`)
into a **single spawn-time lifecycle task** per run, plus a **reap-aware pid guard** shared
by every path that kills/samples by bare pid.

- **B2** — arm the cancel→kill task at *spawn* (`runner.rs` `launch`/`start`), holding a
  `Weak<ProcessGroup>` (own-group) or the reap-aware pid (shared-group); store the handle so
  `Drop` aborts it. Kill is then guaranteed regardless of whether a consuming verb runs.
  Consuming paths keep their race only for *synthesizing* `Error::Cancelled`. Rewrite the
  `cancel_on` doc (`command.rs:434-457`) to match — the kill now always happens; drop the
  false "`wait_any`'s stream simply ends" claim about the kill.
- **B1 / L9** — introduce `PidGuard` (an `Arc<Mutex<Option<u32>>>` or `Arc<AtomicBool>`
  "reaped"). Every reap path sets it: `backend_wait` success, `wait_exit`
  (`mod.rs:594`), `has_exited_now`'s `try_wait` (`mod.rs:1020`). `kill_direct_child` /
  `graceful_kill_pid` / `kill_via_weak` / the profile sampler check it and no-op once
  reaped. Also call `abort_watchdogs()` from `wait_exit` and the probes (closes the common
  minutes-later fire). `pid()` returns `None` after reap (honors its doc). Residual sub-µs
  window documented as the existing `graceful_kill_pid` tradeoff already is.
- **B7 / L18** — anchor the deadline at `started: Instant` (already recorded, unused),
  armed once by the spawn-time lifecycle task so it fires the same wall-clock regardless of
  when a verb/stream/probe consumes. Probes (`probes.rs`) respect it. One clock → a watchdog
  kill always reports `timed_out() == true`. `Error::Timeout` records the real deadline (no
  "0ns").
- **B6** — the `profile()` sampler stored so future-drop tears it down (route through the
  same lifecycle handle / store on `self`, not a frame-local `JoinHandle`).
- **L4** — bias the cancel arm in the `select!` (or route cancel through immediate hard-kill
  regardless of `grace`) so cancellation's "always immediate hard kill" contract holds even
  when it ties with the deadline.
- **L14** — read the cancel token *before* the up-to-5s `join_pumps`, or preserve captured
  output on a cancel that lands during teardown (don't convert a real success to
  `Err(Cancelled)` with output lost).
- **B15** (sys, pgroup) — `Tracked` prune-on-reap hook: untrack a leader when its child is
  reaped, closing the unbounded `killpg(recycled)` window. `pgroup.rs:91-111`, `:309-313`.
- **L7** (sys, windows) — guard `suspend()`/`resume()` against pid reuse between
  `job_member_pids()` and the thread walk (re-check membership, or accept+document; lowest
  priority of the cluster). `windows.rs:266-310`.
- **L11** — align `graceful_kill_pid`'s EPERM handling with `Tracked::exists` (EPERM = alive,
  not gone). `stream.rs:436-441`.

## Phase B — Result shape (D1 + D2) — *gated by Decision 1; do here if "now"*

Same consuming-path functions as A — land while fresh.

- **D1** — `wait`/`finish_streamed`/`finish_events`/`wait_any`/`wait_all` return `Outcome`
  (not `Option<i32>`); `finish_streamed` returns a named `StreamedFinish { outcome, stderr }`
  not a bare tuple. `mod.rs:582`, `stream.rs:159`, `:345`, `lib.rs:269,328`.
- **D2** — `Outcome::Signalled(Option<i32>)` carries the signal number (read
  `ExitStatusExt::signal()` in `backend_wait`, `mod.rs:866`); replace the synthesized
  `Error::Io("…terminated by a signal…")` with `Error::Signalled { program, signal }`
  (`result.rs:191-196`). Make `is_*` / classifiers aware.

## Phase C — Output-capture integrity

Pump / sink / finish machinery.

- **B5** — `finish_streamed`/`finish_events` drain the untaken stdout through a
  policy-aware counted sink (or at least bounded + fail-loud-aware), not `read_to_end` into
  an unbounded `Vec`; abort the drain task in teardown. `stream.rs:167-174`, `:347-352`.
- **B9** — `wait`/`profile` use a true retain-nothing sink (push→drop per line), not
  accumulate-then-discard, so a chatty long-lived child doesn't grow O(total) heap.
  `mod.rs:43-50`, `:696-738`.
- **B10** — bulk verbs after streaming: detect "readers already taken" → either error
  clearly, or correctly join the streaming pumps and check *their* sinks (so output isn't
  silently empty and fail-loud/handler guarantees hold). `mod.rs:457-568`.
- **L1** — don't overwrite `self.stdout_sink` with a fresh closed sink on a repeat
  `stdout_lines`/`output_events` call (preserve the first pump's overflow flag + count).
  `stream.rs:77-94`, `:263-275`.
- **L3** — store/abort the bulk-path pumps (or join on early-`Err`) so a shared-group
  handle's orphaned pumps don't buffer unboundedly. `mod.rs:704-712`, `:525`.
- **L2** — multi-consumer stderr `SharedLines`: either forbid a second `OutputEvents`
  (error) or fix the `notify_one`→`notify_waiters` so neither consumer parks forever.
  `stream.rs:277-292`, `pump.rs:95-110`.

## Phase D — Program-resolution honesty

- **B8** — use `find_in_path`'s found result (`runner.rs:323`): if the program *was* found
  but the OS still refused it (`.cmd` on Windows / missing shebang interpreter), don't claim
  "not found on PATH" — produce a distinct message/variant for found-but-unlaunchable.
- **L20** — `is_bare_name("git/")` → `false` (a trailing separator is path-ish).
  `command.rs:1160-1164`.
- **L21** — keep the full `PATH` value out of `Error::NotFound`'s Display / out of the
  tracing event (`runner.rs:152-159`), honoring lib.rs's "never logs environment values".
- **L13** — fix or down-scope the Windows `quote_arg` "readable and unambiguous" claim
  (trailing backslash, `\"`, `( ) !`, `%`). Display-only. `command.rs:1127-1147`.

## Phase E — Pipeline correctness

- **B11** — *(per Decision 4)* honor inner-stage `ok_codes` in the cleanliness test
  (`pipeline.rs:244-247`) + document; keep last-stage policy.
- **L15** — unchecked-last pipefail preserves the real exit code, not fabricated
  `Some(0)`. `pipeline.rs:259-272`.
- **L19** — pipefail attribution → the culprit (rightmost failing / non-SIGPIPE), not the
  upstream SIGPIPE victim. `pipeline.rs:244-247`.
- **L16** — `ProcessResult::combined` joins stdout/stderr with a separator so the last
  stdout line isn't glued to the first stderr line. `result.rs:250-255`.

## Phase F — Group / limits / sys layer

- **B12** — make `escalate_to_kill(false)` actually skip the `Drop` hard-kill (a backend
  flag the Drop reads, or `shutdown` detaches the group when escalation is off).
  `group.rs:366-385`; backends `windows.rs:557-563`, `linux.rs:293-318`, `pgroup.rs:309-313`.
- **B13** — Linux cgroup limits: implement create-leaf → migrate-self → enable-controllers
  in the now-empty parent (or a delegated subtree), fixing the EBUSY-everywhere failure and
  the misleading error text. `linux.rs:336-342`, `:380-405`.
- **B14** — enforce `max_processes` on Linux direct spawns (post-migration
  `pids.current` admission check), or accept the divergence and document the Linux caveat
  loudly. `linux.rs:410-412` vs `:104-108`/`:533-564`.
- **B16** — reap concurrently during pgroup `graceful_shutdown` (mirror
  `teardown_on_timeout`'s `tokio::join!`) so own-child zombies don't burn the full timeout.
  `pgroup.rs:276-294`.
- **L6** — pgroup fallback: don't permanently prune a just-spawned id when a signal sweep
  races the child's between-fork-and-exec `setpgid` (ESRCH on a fresh pid ≠ "gone forever").
  `pgroup.rs:180-187`.
- **L8** — fix the `job_member_pids` flexible-array provenance-UB (`&raw const …` from the
  buffer pointer, not `as_ptr()` on the `[_;1]`). `windows.rs:495`.
- **L10** — document the cgroup-vs-Job `stats()` semantic divergence (live-members-only sum
  vs job-wide incl. terminated). `stats.rs:22-37`.

## Phase G — Security / hygiene

- **B4** — *(per Decision 3)* redact `Command`/`CliClient`/`Invocation` Debug.
  `command.rs:1066-1068`, `client.rs:48`, `doubles.rs:392-404`.
- **B18** — cassette: scope the "can't leak secrets" claim to env values only; warn that

- **L22** — manual `Error` Debug that bounds the `Exit` streams like Display's 200-byte cap

- **L23** — cassette replay key collision on lossy UTF-8: key on raw bytes (or document the
  exotic-input limitation). `cassette.rs:107-131`.

## Phase H — Stdin

- **B3** — *(per Decision 2)* surface the stdin-writer failure: stash a non-broken-pipe
  error (`self.stdin_error`), new `Error::Stdin { program, source }`, returned by consuming
  paths when the run otherwise succeeded. `mod.rs:787-814`, `runner.rs:341-362`,
  `stdin.rs:114-146`.
- **B17** — release the `Stdin` source mutex after `take()` (don't hold the guard across
  `tokio::io::copy`), so a concurrent second run gets prompt EOF instead of stalling.
  `stdin.rs:125-144`.
- **L5** — `wait_any`/`wait_all` close an untaken `keep_stdin_open` pipe (lift the
  `drive_to_exit` close into the race path) so a stdin-reading child doesn't hang the race.
  `mod.rs:594-596` vs `:833-841`.
- **L12** — doc fixes: `run`/`run_unit` "require a zero exit" → note `ok_codes` widens;
  `Command::env`'s false "`None` value removes". `command.rs:156,1008-1009`,
  `runner.rs:63,74`.

## Phase I — Design block (rest of D, *gated by Decision 1*)

- **D3** — `Supervisor` capture default: bounded tail (or explicit `capture(policy)` knob)
  so the keep-a-server-alive use case doesn't accumulate every incarnation's full output.
  `supervisor.rs:324`, `command.rs:111`.
- **D4** — split `ProcessStarter: ProcessRunner` (or make `start` required) so "can't
  stream" is a compile error, not runtime `Unsupported`. `runner.rs:37-43`,
  `cassette.rs:196-200`.
- **D5** — `StdioMode::Inherit`/`Null` make the capture verbs return a clear
  error (or documented tri-cause) instead of silently empty. `stream.rs:78-93`, `:264-274`.
- **D6** — `Command::first_line` delegates through a `ProcessRunnerExt::first_line` so it's
  reachable via the test seam. `command.rs:1024-1059`.
- **D7** — remove the `cli_client!` macro (zero users; the hidden `#[macro_export]` helper
  is permanent public API) in favor of the documented hand-rolled wrapper, or document the
  hidden-macro contract as API. `client.rs:258-346`.
- **D8** — decide which tokio-typed signatures are 1.0 surface vs `#[doc(hidden)]`/escape
  hatches; make `ProcessGroup::spawn` take its command by value (no hook-stacking on reuse).
  `command.rs:836`, `group.rs:192,226`, `stdin.rs:76`.
- **D9** — misc: `Invocation::cwd` → `PathBuf`; decouple `timeout_signal` from the
  `process-control` feature; make `unbounded().with_overflow(Error)` a hard error not a
  no-op; alternate `OutputEvents` poll priority for stdout/stderr fairness.
  `doubles.rs:399`, `command.rs:412`, `buffer.rs:111-121`, `stream.rs:570-599`.
- **D10** — a `RunningProcess` accessor for kill-on-drop provenance (own-group vs
  shared-group) so a receiving function can reason about drop safety.

## Suggested execution order

A → B *(if "now")* → C → **D, E, F, G, H in any order / parallelizable** → I *(if "now")*.
A/B/C share the consuming-path core (sequence them); D/E/F/G/H touch disjoint subsystems
(runner+command, pipeline, sys, cassette+client, stdin) and carry no cross-dependency.
Each phase is its own jj change stacked on `main`, nothing pushed until the explicit signal.
