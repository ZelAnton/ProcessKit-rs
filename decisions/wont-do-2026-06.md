# Won't do — verdicts from the 2026-06-09 development sweep

> **Status:** decision record / closed. These candidates surfaced during the
> 2026-06-09 cross-language borrowing + scope sweep and were rejected as scope
> boundaries. Recorded so they aren't re-proposed. A concrete consumer with a new
> argument can reopen any of them (move to [`../ideas/`](../ideas/)). Sibling:
> [`architecture-audit-2026-06.md`](architecture-audit-2026-06.md) (the standing
> rejected/confirmed-sound list).

## TL;DR

| Candidate | Verdict | Why not |
|---|---|---|
| Built-in shell mode (`sh -c` / `cmd /c` convenience) | **Reject** | Cuts against the deliberate shell-free design; injection/quoting hazards. The `to_tokio_command()` escape hatch covers the rare real need. |
| IPC / structured message passing (execa `sendMessage`/`ipcInput`) | **Reject** | Assumes a Node-style child protocol over a side channel; not a general subprocess concern. Out of scope. |
| `detached`/disown as a **default or headline** feature | **Reject** (as default) | Directly opposes the kill-on-drop guarantee. *One* deliberate, documented escape hatch is tracked in [`../ideas/later-detached-handoff.md`](../ideas/later-detached-handoff.md) — but never the default. |
| `miri` in CI | **Reject** (low value) | The crate's `unsafe` is almost entirely OS FFI/syscalls (Job Objects, cgroup writes, `pre_exec`, `libc`) that miri cannot execute. It would cover almost none of the actual unsafe surface. Revisit only if a substantial pure-Rust unsafe path appears. |
| Object-mode / transform output streams (execa) | **Reject** | JS-runtime-specific ergonomics; the `on_*_line` handlers + encoding overrides already cover Rust-side line transforms. |
| Bare `Command::output` (collapse `output_string`/`output_bytes`) | **Reject** (already) | Restated from `architecture-audit-2026-06.md` — the payload split is intentional. |

## Notes

These are *boundaries*, not gaps. The throughline: ProcessKit is a **containment +
async-capture** library with a **shell-free, kill-on-drop** identity. Features that
erode that identity (shell mode, detached-by-default) or that belong to a different
problem (child IPC protocols, JS-style object streams) stay out, even when a
sibling library in another ecosystem ships them.
