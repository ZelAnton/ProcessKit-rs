# Won't do — verdicts from the 2026-06 development sweeps

> **Status:** decision record / closed. These candidates surfaced during the 2026-06
> cross-language borrowing + scope sweeps (2026-06-09 and 2026-06-10) and were rejected as
> scope boundaries. Recorded so they aren't re-proposed. A concrete consumer with a new
> argument can reopen any of them (move to [`../ideas/`](../ideas/)). Sibling:
> [`architecture-audit-2026-06.md`](architecture-audit-2026-06.md) (the standing
> rejected/confirmed-sound list).

## TL;DR — 2026-06-09 sweep

| Candidate | Verdict | Why not |
|---|---|---|
| Built-in shell mode (`sh -c` / `cmd /c` convenience) | **Reject** | Cuts against the deliberate shell-free design; injection/quoting hazards. The `to_tokio_command()` escape hatch covers the rare real need. |
| IPC / structured message passing (execa `sendMessage`/`ipcInput`) | **Reject** | Assumes a Node-style child protocol over a side channel; not a general subprocess concern. Out of scope. |
| `detached`/disown as a **default or headline** feature | **Reject** (as default) | Directly opposes the kill-on-drop guarantee. *One* deliberate, documented escape hatch is tracked in [`../ideas/later-detached-handoff.md`](../ideas/later-detached-handoff.md) — but never the default. |
| `miri` in CI | **Reject** (low value) | The crate's `unsafe` is almost entirely OS FFI/syscalls (Job Objects, cgroup writes, `pre_exec`, `libc`) that miri cannot execute. It would cover almost none of the actual unsafe surface. Revisit only if a substantial pure-Rust unsafe path appears. |
| Object-mode / transform output streams (execa) | **Reject** | JS-runtime-specific ergonomics; the `on_*_line` handlers + encoding overrides already cover Rust-side line transforms. |
| Bare `Command::output` (collapse `output_string`/`output_bytes`) | **Reject** (already) | Restated from `architecture-audit-2026-06.md` — the payload split is intentional. |

## TL;DR — 2026-06-10 sweep

The 2026-06-10 sweep (run after `0.9.1` shipped items 1–9) found the idea space already
well-mapped; most candidates were already filed or settled. These four new candidates were
assessed and rejected:

| Candidate | Verdict | Why not |
|---|---|---|
| `clear_env()` verb (start child from an empty environment) | **Reject** (redundant) | `inherit_env([])` (empty allow-list) already clears-then-copies-nothing = a cleared env. A second verb for the same effect is surface bloat; at most a one-line doc note on `inherit_env`. |
| `arg_if` / `args_opt` conditional-arg builder sugar | **Reject** (scope-creep) | Callers express this in one inline line (`if v { cmd = cmd.arg("-v") }`); adding it invites a combinatorial family on the most-used builder for cosmetics. Consistent with the audit's rejection of cosmetic surface. |
| Redaction of env-var **names** in `command_line()` / tracing / cassettes | **Reject** (no consumer) | The crate's secret hygiene is already strong — argv/env *values* are never logged and cassettes store env *names* only. Hiding the names too serves a threat model no consumer has raised and doesn't strengthen containment/capture. |
| Finer interactive-stdin flush / half-close timing knobs for REPLs | **Reject** (subsumed) | REPL line-discipline subtleties are PTY territory (deferred in [`../ideas/later-pty-support.md`](../ideas/later-pty-support.md)); the named gap is covered by the filed `send_control` ([`../ideas/next-launch-ergonomics.md`](../ideas/next-launch-ergonomics.md) E). No separate value over the existing `standard_input()`/`write_line`/`finish`. |

(Two candidates from the same sweep were *not* rejected — they're real but small: an
`OverflowMode::Error` ceiling folded into [`../ideas/next-output-handling.md`](../ideas/next-output-handling.md),
and a pluggable buffer-policy seam filed as [`../ideas/later-buffer-policy-seam.md`](../ideas/later-buffer-policy-seam.md).
A third, a typed invalid-UTF-8 decode mode, was dropped as already-handled: the pump
decodes lossily by default — recorded in the output-handling idea so it isn't re-proposed.)

## Notes

These are *boundaries*, not gaps. The throughline: ProcessKit is a **containment +
async-capture** library with a **shell-free, kill-on-drop** identity. Features that
erode that identity (shell mode, detached-by-default) or that belong to a different
problem (child IPC protocols, JS-style object streams) stay out, even when a
sibling library in another ecosystem ships them.
